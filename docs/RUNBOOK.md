# Как это работает

Два агента в двух разных CLI работают над одной задачей без вашего участия.
Один пишет код, второй его ломает. Канал между ними — MCP-сервер `pair`.

## Пять частей

| что | где | зачем |
|---|---|---|
| сервер | `mcp/pair_mailbox/server.py` | канал и правила: один писатель, патчи с хешем, аудит |
| конфиг OpenCode | `~/.config/opencode/opencode.jsonc` | регистрирует `pair` в OpenCode, глобально |
| конфиг Antigravity | `~/.gemini/config/mcp_config.json` | регистрирует `pair` в agy, глобально |
| скилл | `~/.config/opencode/skills/pair-work/SKILL.md` и та же в `~/.gemini/config/skills/` | вся логика цикла: план → код → ревью → PR |
| ваш орган управления | `~/work/umputum/bin/pairctl` | единственный способ сменить писателя |

## Словарь

- **роль** — имя процесса: `opencode` или `agy`. Зашито в конфиге, агент не может её выбрать.
- **писатель** — агент, который сейчас держит право править файлы. Он же коммитит и пушит.
- **критик** — второй агент. Читает, спорит, пишет замечания. Файлы не правит никогда.
- **claim** — захват права писать. Кто первый, тот и пишет. Гонка, и это нормально.
- **патч** — файл с предложенным изменением. Критик его создаёт, писатель проверяет хеш и применяет.
- **pair_note** — долговременная заметка в `.pair/notes/`. Общая память, переживает перезапуск.
- **pairchat** — просмотр переписки в третьей панели.
- **`.pair/`** — состояние конкретного проекта. Там ящик, заметки, трейл, патчи. Можно удалять.

## Запуск

Две сессии agterm в одной папке: одна `opencode`, другая `agy`.

В **любом** окне агента напишите:

```
работаем вместе: <задача>
```

Второе окно можно не трогать — агент разбудит соседа сам. Если второй не проснулся,
напишите туда то же самое.

Больше ничего. Дальше они сами до упоя.

## Наблюдение

В третьей сессии:

В папке проекта — только этот проект. Без флагов:

```sh
cd ~/work/ваш-проект && ~/work/umputum/bin/pairchat --once
```

Показывает: сообщения обоих, отказы, смену писателя, заметки. Цветом помечено:
красный — отказ, жёлтый — захват авторитета, сиреневый — заметка, белый — переписка.

`--once` печатает и выходит. Без него — окно до Ctrl-C.

Смешивать проекты по умолчанию нельзя: в пяти переписках вперемешку вы не
разберётесь, где ваша. `--all` — отдельное сознательное действие.

### Фильтры

```sh
bin/pairchat --once --messages-only   # только переписка, без служебных строк
bin/pairchat --once --no-notes         # без заметок
bin/pairchat --once --since 60         # только то, что за последний час
bin/pairchat --once --all-notes        # включая рабочие заметки о самом pair-mailbox
```

Заметки агентов (`plan`, `finding`, `decision`, `review`, `verdict`, `handoff`)
показываются всегда. Остальное — мои рабочие заметки, сотни строк кода, они
скрыты: в переписке агентов им не место.

## Несколько проектов сразу

```sh
~/work/umputum/bin/pairctl all
```

Одна строка на проект: фаза, кто пишет, кто критик, как давно молчат, задача.

```sh
~/work/umputum/bin/pairchat --all --once
```

Та же шапка, под ней вся переписка по всем проектам, у каждой строки метка проекта.
Сортировка по времени, так что видно, кто с кем перекрёстно работает.

Один конкретный проект, не смешивая с остальными:

```sh
bin/pairchat --once ~/work/blog
```

Где искать проекты: `~/work/*/.pair` по умолчанию. Своё — через `PAIR_SCAN`:

```sh
PAIR_SCAN='~/work/*/.pair:~/src/*/.pair' ~/work/umputum/bin/pairctl all
```

Назвали проект в аргументах — ищете только его: `pairctl all ~/work/blog`.

Код возврата `3` — есть зависшие. Скриптом это ловится: `pairctl all || alert`.

## Разово — без цвета, только факты

```sh
cd <проект> && ~/work/umputum/bin/pairctl status # кто пишет, задача, фаза
cd <проект> && ~/work/umputum/bin/pairctl log --limit 10   # что делали
cd <проект> && ~/work/umputum/bin/pairctl notes   # их выводы
```

## Что они делают за 4 круга

1. **План.** Писатель изучает код, пишет план в заметку, отправляет критику.
   Критик ищет дыры в плане, писатель переписывает.
2. **Код.** Писатель делает по плану, запускает тесты. Нет зелёных тестов — круга нет.
3. **Ревью.** Критик читает дифф целиком. Находки — в заметки с `file:line`.
   Настоящие и ложные отдельно, ложные — с вердиктом почему.
4. **Повтор.** Настоящие исправлены, тесты зелёные, критик подтвердил → verify → done.

Потолок 4 круга, потом останавливаются и пишут, что не сошлось.

В конце: своя ветка, коммит, push, PR. В `main` не пушат никогда.

## Где они останавливаются

Только шесть вещей: `.env`, секреты и токены, порты и адреса развёртывания, деплой,
миграции БД, удаление данных или истории git.

Всё остальное, включая неопределённость, решают между собой и пишут в заметку с причиной.

## Ваше действие

Только если завис один из агентов:

```sh
cd <проект> && ~/work/umputum/bin/pairctl release
cd <проект> && ~/work/umputum/bin/pairctl assign agy
```

И сказать обоим в их окнах, кто теперь пишет. Иначе старый писатель продолжит править файлы.

## Если что-то сломалось

| симптом | причина | лечение |
|---|---|---|
| агент не видит `pair_state` | сервер не зарегистрирован | `opencode service restart`, перезапуск agy |
| в `/mcp` нет `pair` | конфиг с ошибкой | проверить `~/.gemini/config/mcp_config.json`, ключ для удалённого сервера — `serverUrl` |
| `pairctl` пишет не в тот проект | скрипт запущен не из папки проекта | делать `cd <проект>` перед вызовом |
| `agy` спрашивает разрешение на каждый вызов | режим Ask | `/permissions` → `A` → `mcp(pair/*)` |
| в логе пусто, а агенты отвечают | они не вызвали `pair_send` | скажите прямо: «вызови `pair_send` соседу» |
| `error: no connector can handle spec` | неверный транспорт в конфиге | для удалённого `serverUrl`, для локального `command` |

## Что перепроверять после обновлений

Оба CLI выкатывают по несколько раз в неделю. Ломается обычно конфиг, не логика.

```sh
opencode --version
```

- схема любого поля: <https://opencode.ai/config.json>, раздел `$defs`
- типы плагина: `~/.opencode/node_modules/@opencode-ai/plugin/dist/v2/promise/context.d.ts`

Сервер написан на чистом MCP и не зависит ни от одной версии — ломаться ему не по чему.

## Чего здесь нет

- Общего экрана. Агенты общаются через диск, не одновременно. `pairchat` показывает
  лог, а не живой разговор как в общей комнате.
- Прогона по расписанию. Нет аналога ralphex с веб-дашбордом и изоляцией в worktree.
- Независимого аудита тестов. Критик может не заметить, что тест замокан или пропущен.
