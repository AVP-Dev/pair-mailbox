---
title: install.sh ломается на комментарии в opencode.jsonc
found: 2026-10-03
severity: medium
---
## Где

`install.sh:21` — `cfg = json.loads(p.read_text()) if p.exists() else {}`
`install.sh:28` — `p.write_text(json.dumps(cfg, indent=2))`

## Что сломается

`install.sh:20` открывает `~/.config/opencode/opencode.jsonc` — jsonc, то есть JSON **с
комментариями и висячими запятыми**. На `install.sh:21` он читает этот файл обычным
`json.loads`, который комментарии не понимает.

Как только в `opencode.jsonc` появится хоть одна строка `// ...` или одна висячая
запятая, `install.sh:21` бросит `JSONDecodeError`, `set -eu` (строка 8) оборвёт
установку с ненулевым кодом. К этому моменту навыки (строка 12) и
`~/.gemini/config/mcp_config.json` (строки 32–37) уже перезаписаны — установка
останется наполовину сделанной.

Даже если парсинг случайно пройдёт, `install.sh:28` переписывает файл через
`json.dumps`: все комментарии и форматирование пользователя теряются безвозвратно.
Это прямо противоречит обещанию в шапке скрипта, «Чужие ключи конфигов не трогает».

Проверено: на текущем `~/.config/opencode/opencode.jsonc` (280 байт, комментариев нет)
`json.loads` проходит, поэтому сегодня дефект не проявляется. На файле с одним
комментарием и одной висячей запятой падает:
`JSONDecodeError: Expecting property name enclosed in double quotes: line 2 column 3`.

## Почему отложили

Задача была — разложить заметки из `.pair/notes/` по путям после маркера `>>>`.
Правка `install.sh` меняет поведение установщика и выходит за эти рамки.
Безопасного исправления на минуту здесь нет: снять комментарии значит писать
разбор, который не должен резать `//` внутри строк, а готового jsonc-парсера в
зависимостях проекта нет.

## Что сделать

1. Разбирать `opencode.jsonc` jsonc-совместимым парсером, а не `json.loads`.
   Варианты: `json5` из зависимостей, либо аккуратное снятие `//` и `/* */` с
   учётом экранирования внутри строк.
2. Не переписывать файл целиком. Либо правка по месту с сохранением
   форматирования и комментариев, либо отказ от перезаписи с требованием
   добавить блок `mcp.pair` руками.
3. Тест на два случая: конфиг с комментарием и без, ключ `mcp.pair` отсутствует
   и присутствует. Идемпотентность заявлена в шапке скрипта — проверять надо её.
