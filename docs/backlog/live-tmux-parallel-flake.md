## Где

`mcp/pair_mailbox/test_protocol.py:2801` — `TestSessionAddressing.test_the_same_pane_is_recognised_across_both_formats`

## Что сломается

Тест зелёный соло, красный при двух параллельных полных прогонах. Воспроизведено
критиком: FAILED vs OK на том же HEAD; соло 6/6. Область до раунда 33: код 33 ни при
чём, live-панели общие, два раннера делят tmux-состояние.

## Что сделать

- Дёшево: гонять live-tmux сюиты последовательно (гейт уже так делает, `--jobs 1`
  по умолчанию) — зафиксировать это правилом в `scripts/verify-project.sh`, а не
  молчаливым соглашением.
- Дорого: hermetic-стаб для `session_address`/`same_pane`, как сделано для
  `find_own_pane` в раунде 32 (стаб-tmux вместо живого). Тогда параллельность
  вообще перестанет быть фактором.
- Тест отходом 30 мин (требование приёмки раунда 33) — отдельно, не в этой карточке.

## Не делать

Не чинить скипом: скип маскирует поломку (урок ВОЗРАЖАЮ-1 раунда 32 — `if-not-found-skip`
не может упасть никогда). Либо последовательный гейт правилом, либо стаб.
