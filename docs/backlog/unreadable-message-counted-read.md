## Где

`mcp/pair_mailbox/server.py:649-655` (`_drain`)

## Что сломается

`_drain` на `OSError`/`JSONDecodeError` делает `continue`, но `seen` увеличивается на
`len(fresh)` — то есть включая пропущенный файл.

Воспроизведено: `pair_read` вернул 1 сообщение, `seen` стал 2, `unread` — 0, битый
файл остался на диске, в транскрипте ни слова, и `pair_read` больше его никогда
не отдаст. Сообщение потеряно без следа — при том, что §11 считает транскрипт
землёй для восстановления.

## Почему отложили

Раунд был в режиме `audit` (`bin/pairctl mode audit`): работа раунда — evidence, а не diff, поэтому правка кода в нём не делалась. Находка подтверждена соседом и ждёт отдельного раунда `fix`.

## Что сделать

1. Продвигать `seen` только на реально прочитанные файлы.
2. Битый файл не пропускать молча: запись в транскрипт (`message_unreadable`) с
   путём, плюс отказ, чтобы агент знал, что чего-то не хватает.
