# pair-discussion-before-work

Симптом 2026-10-07: 40 send за всё время, последние (seq 257–258) с пустым
subject и пустым text — агенты обмениваются пингами, а не обсуждением.
Изначальный замысел (задача → обсуждение → работа) не соблюдается: писатель
сразу пишет код, критик отвечает вердиктом, середина выпала.

Причины:
1. Протокол требует plan в note, но не требует обсуждения плана ДО работы:
   §9 говорит «что agreed», но не «как agree».
2. pair_send с expects_reply открывает obligation, но ничто не требует от
   писателя вынести план на обсуждение до первого коммита.
3. Пустые send (seq 257–258, subject="", text="") — текст уходит не в те поля
   или теряется; надо проверить сериализацию send в server.py + transcript.

Сделать:
1. В §9 (или новый §9a): писатель обязан до первого коммита раунда отправить
   план критику (pair_send с expects_reply, subject=план), критик обязан
   ответить возражением или согласием — только потом код.
2. Починить пустые send: найти, куда девается text (server.py tool_pair_send →
   transcript), добавить тест «send с текстом сохраняет текст».
3. Око Саурона: считать раунды без send-with-text до первого коммита.
   Определение (согласовано в seq 284, исправлено по вердикту seq 286):
   send/advance поля round не несут (только evidence) — окно позиционное:
   последний advance(implement), далее план писателя, далее evidence(commit).
   План = subject содержит план|plan (case-insensitive). Источник: активный
   `.pair/transcript.jsonl` + `.pair/transcript-archive/*.jsonl` (mailbox для
   тика непригоден — там тоже нет round). Метрика в строке тика: `discuss=ok`
   (план внутри окна до коммита) или `discuss=miss` (иначе). Ротированный
   архив читается только когда активного журнала не хватило — один проход
   по строкам с подстрочным фильтром, без полного разбора.

Нит (из вердикта seq 286, не чинить здесь): subject из одних пробелов truthy —
transcript сохранит пробелы без fallback (server.py:2109). Кандидат в отдельный
раунд: strip-check на subject в tool_pair_send.
