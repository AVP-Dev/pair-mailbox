## Где

`docs/backlog/install-sh-jsonc-comments.md:8` (`:21`), `:17-18` (set -eu),
`:25`, `:31` — против `install.sh:83`, `:84-86`, `:93`, `:180-182`

## Что сломается

Запись верна по сути и неверна по исполнению:

| В записи | Сейчас |
|---|---|
| `install.sh:21` — чтение | `install.sh:83` (`sed -n '20,22p'` даёт текст `NOTE`) |
| `install.sh:28` — запись | `install.sh:93` |
| `set -eu` (строка 8) оборвёт установку | `set -eu` в `install.sh` нет вообще, это `serve.sh`; скрипт теперь Python |
| установка падает | `except` на `install.sh:84-86` печатает `!! не читается`, возвращает `None`, `main` идёт в `continue` (`install.sh:180-182`): профиль молча не получает ни навыков, ни инструкций, выход 1 |

Суть дефекта жива: `install.sh:83` по-прежнему читает `opencode.jsonc` через
`json.loads`, а `install.sh:93` перезаписывает файл целиком через `json.dumps` —
комментарии пользователя теряются.

Тот, кто возьмёт запись в работу, откроет `install.sh:21` и найдёт текст
докстринга. Противоречие ровно то, которое проект ищет в чужом коде, а лежит
в его собственном выходном каталоге.

## Почему отложили

Раунд был в режиме `audit` (`bin/pairctl mode audit`): работа раунда — evidence, а не diff, поэтому правка кода в нём не делалась. Находка подтверждена соседом и ждёт отдельного раунда `fix`.

## Что сделать

1. Обновить запись под текущий `install.sh` (строки, отсутствие `set -eu`, поведение
   через `continue`).
2. Ввести правило: перед началом работы по backlog-записи перепроверять её
   `file:line`, потому что это единственное место, где ссылки заведомо протухают.
