## Где

`bin/pairpilot` — `unread_peers` (830), `remember` (312), `forget` (320, мёртв), `enqueue` (646).

## Что сломается

1. **unread-штамп — утечка.** `unread_peers` ставит штамп `unread-{role}` через
   `remember()` при первом непрочитанном. При `missing <= 0` (агент прочитал)
   штамп НЕ удаляется, `forget()` нигде не вызывается. Итог: второе письмо
   агента уже не будит — пилот молчит, пока письмо не протухнет в ящике.
   Живого проявления не было (пилот молчит с 08.10 01:18), баг найден
   чтением кода в раунде 42.
2. **enqueue затирает молча.** `enqueue()` — голый `write_text`: новый текст
   вытесняет недоставленный без следа в транскрипте. В аудите напоминание
   выглядит «не бывшим».
3. **reply без повтора.** Штамп `reply-{seq}-{receiver}` без раунда и без TTL:
   зависший запрос напоминает один раз за всё время.

## Что сделать

- При `missing <= 0` удалять штамп `unread-{role}` (чище варианта
  `unread-{role}-{seq}`): штамп живёт, пока есть непрочитанное.
- В `enqueue` при вытеснении писать `pilot_outbox_replaced`
  (to=role, old=old[:120], new=text[:120]).
- Повтор `reply-{seq}` раз в 2 часа по mtime штампа.
- Тесты: второе письмо после прочтения будит; вытеснение видно в транскрипте;
  повтор reply по TTL.

## Не делать

Не трогать `stale_writer` (там штамп с раундом — корректен) и переживающую
доставку через `mailbox_fallback` (задумана).
