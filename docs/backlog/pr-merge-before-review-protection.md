## Где

- Процесс слияния веток / командный workflow писателя (`docs/PROTOCOL.md` §6, §10b).
- GitHub branch protection rules (master).
- Возможный CLI-помощник финализации (например, `pairctl merge` или guard перед `done`).

## Что это

В раунде 59 писатель смержил ветку `feat/worktree-isolation` в `master` через `gh pr merge` до того, как критик оставил подтверждённый вердикт по PR в фазе `verify`.
Сервер `pair_mailbox` заблокировал перевод раунда в `done` по правилу stale review:
`последний вердикт omp/verdict stale относительно HEAD: HEAD уехал без списка файлов`.
Тем не менее, на уровне git-репозитория код уже попал в `master` без аппрува критика, что нарушает фундаментальный инвариант двух-агентной парной работы.

## Что сделать / критерий приёмки

1. Закрепить жесткий инвариант: слияние PR в `master` разрешено производить **только** после получения актуального вердикта `approve` от критика в фазе `verify`.
2. Встроить машинную проверку: команда или скрипт слияния проверяет наличие актуального, не-stale вердикта критика в `.pair/notes/` перед выполнением `gh pr merge` / `git merge`.
3. Включить защиту ветки `master` в GitHub: требовать обязательное прохождение review перед merge.
