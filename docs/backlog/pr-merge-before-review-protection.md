## Где

- Процесс слияния веток / командный workflow писателя (`docs/PROTOCOL.md` §6, §10b).
- GitHub branch protection rules (`master`).
- CLI-помощник финализации `pairctl pr merge` с машинным гейтом.
- Сверхвизор `bin/pairpilot` (таймауты, эскалация человеку).

## Что это

В раунде 59 писатель смержил ветку `feat/worktree-isolation` в `master` через `gh pr merge` до того, как критик оставил подтверждённый вердикт по PR в фазе `verify`.
Сервер `pair_mailbox` заблокировал перевод раунда в `done` по правилу stale review:
`последний вердикт omp/verdict stale относительно HEAD: HEAD уехал без списка файлов`.
Тем не менее, на уровне git-репозитория код уже попал в `master` без аппрува критика, что нарушает фундаментальный инвариант двух-агентной парной работы.

## Архитектурные принципы и критерии приёмки

1. **Feature Freeze в фазе `verify`**:
   - Вход в `verify` фиксирует точный commit SHA в PR.
   - Любые новые коммиты писателя во время фазы `verify` запрещены, чтобы предмет ревью не менялся на лету.
2. **Машинный гейт слияния (`pairctl pr merge`)**:
   - Прямой вызов `gh pr merge` / `git merge` запрещен правилами протокола.
   - Команда `pairctl pr merge` проверяет:
     1. Текущая фаза — строго `verify`.
     2. Наличие не-stale вердикта `approve` от критика, привязанного к текущему HEAD SHA.
     3. Полный прогон тестов (`pair_evidence(kind="test", ok=true)`).
3. **Фиксация причин reject в артефакте**:
   - При `reject` критик обязан указать конкретный список файлов, строк и причину отказа в артефакте (`.pair/notes/verdict.md` или структурированном JSON).
   - Раунд откатывается `verify → implement`, задача возвращается писателю с привязкой к замечаниям.
4. **Строгая эскалация таймаутов человеку**:
   - При зависании/отставании критика писатель **ни при каких условиях** не имеет права самовольно аппрувить свой PR или обходить гейт.
   - По таймауту супервизор `bin/pairpilot` переводит статус в эскалацию человеку (`pairup --swap <cli>` или ручной `pairctl ok`).
5. **Аппаратная защита в GitHub**:
   - Включение branch protection на ветку `master`: запрет прямых пушей, требование PR review approval перед слиянием.
6. **Разнородность пар (CLI & Model Diversity)**:
   - Не допускать работы на одинаковых моделях с одинаковыми слепыми зонами; критик должен запускаться на независимом раннере (например, Claude/Codex/OMP против Antigravity/OpenCode) и гонять независимые статические чеки.
