## Где

`mcp/pair_mailbox/review_gate.py:108` — `content.split("\n## ")`, затем `last_block = blocks[-1]`, маркер APPROVED/NEEDS WORK ищется только в нём.

## Что сломается

Вердикт с `**NEEDS WORK**` наверху и секциями `##` ниже читается гейтом по последней секции («What this does NOT cover») — маркера там нет, отказ звучит как «no structured marker» вместо «rejected the changes». Мёрж блокируется в обоих случаях (небезопасно не было), но машина не отличает reject от опечатки; симметрично approval-shaped строка не в том блоке может спрятаться так же.

## Почему отложили

Найдено критиком opencode при подаче вердикта раунда 95, вне скоупа задачи 111. Конвенция + гейт, не аудит бэклога.

## Что сделать

Одно из двух: (a) конвенция в skill + PROTOCOL §10b — тело вердикта один блок без `##`, детали прозой/пунктами; (b) гейт ищет блок С маркером (последний matching, не последний). Приёмка: вердикт из трёх секций с маркером в первой даёт «rejected/approved» по маркеру; маркер в последней — как сегодня.
