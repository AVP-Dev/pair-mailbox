# Структура проекта и порядок в файлах

[English](project-structure.md) · [Участие](../CONTRIBUTING.md)

## Ответственность

| Путь | Что содержит |
|---|---|
| `mcp/pair_mailbox/` | MCP-сервер, состояние, права, транспорт и координацию |
| `bin/` | запуск проектов, инструменты оператора и супервизор |
| `cli-profiles.json` | профили конфигурации и запуска CLI |
| `install.sh`, `finish.sh` | установку интеграций и обслуживание |
| `scripts/` | гейты проверок, карту наборов, аудит и проверки порядка |
| `skills/` | основные навыки для копирования в каталоги CLI |
| `.agents/`, `.opencode/` | определения агентов и плагинов этого репозитория |
| `docs/` | актуальные руководства, протокол и политику проекта |
| `docs/backlog/` | подтверждённый открытый долг; после слияния исправления карточка удаляется |
| `docs/rounds/`, `docs/archive/` | историю, а не актуальные инструкции запуска |
| `.pair/` | игнорируемое состояние, сообщения, патчи, доказательства и логи |
| `.worktrees/`, `.venv/` | игнорируемые локальные рабочие окружения |

Клон движка и целевой проект могут быть разными репозиториями. Запуск определяет
состояние проекта и разрешённый движок. После перехода в другой проект нельзя
использовать относительные пути к скриптам движка.

## Размер файлов

| Размер | Требование |
|---|---|
| до 300 строк | обычная цель |
| 300–500 | одна объяснимая ответственность |
| 500–800 | проверка границы модуля |
| более 800 | обоснованное исключение в baseline |

Актуальные потолки и причины хранятся только в
[`file-size-baseline.tsv`](../scripts/file-size-baseline.tsv). Фактические размеры
показывает `./scripts/file-size-gate.sh`: скопированная таблица быстро устаревает.
Потолок — максимум, а не требуемый объём. Увеличивайте его только для обоснованной
правки, а не ради сокрытия непроверенного превышения.

## Проверка

Из клона движка:

```bash
./scripts/verify-changed.sh
./scripts/verify-project.sh --list
./scripts/verify-project.sh --jobs 1
```

Профиль задаёт выполняемые проверки, карта выбирает наборы по изменённым файлам.
Новому исполняемому инструменту нужны проверки поведения либо обоснованное исключение
в `scripts/bin-test-exemptions.json`. Тесты располагаются рядом с исходником;
общие фикстуры используйте вместо второго конкурирующего тестового модуля.

## Рефакторинг и чистка

Держите реализацию внутри ответственного модуля, межмодульные договорённости делайте
явными. Делите модули, когда этого требует ответственность или безопасная проверка.
После переноса кода проверяйте затронутое поведение. Массовая декомпозиция — отдельная
задача, а не скрытое условие исправления другого дефекта.

Исключайте из Git сгенерированные окружения и отчёты. Сохраняйте нужную историю
состояния и отличайте архив решений от актуальных руководств.
