# Установка

[English](SETUP.md) · [Быстрый старт](../README.ru.md) · [Рабочие команды](RUNBOOK.ru.md)

## Зависимости

Нужны Python 3.8+, Git, tmux и современный Bash. Сами CLI агентов устанавливаются
и авторизуются отдельно. Движок не предоставляет доступ к моделям и не выбирает их.

Ubuntu/Debian:

```bash
sudo apt-get update
sudo apt-get install python3 python3-venv git tmux
```

macOS с Homebrew:

```bash
brew install python bash git tmux
export PATH="$(brew --prefix)/bin:$PATH"
```

Проверьте, какие команды выбрала оболочка:

```bash
python3 --version
bash --version
git --version
tmux -V
```

Проверки используют `wait -n`: нужен Bash 4.3+, рекомендуется Bash 5.
Полный набор тестов процессов и tmux рассчитан на Linux. Поддержка запуска на
macOS не означает переносимость всех Linux-зависимых тестов.

Основной MCP-сервер использует стандартную библиотеку Python. PyNaCl необязателен
для обычного транспорта; он нужен для подписей ролей Ed25519 и полного набора тестов.
Для разработки используйте виртуальное окружение из [Contributing](../CONTRIBUTING.md).

## Установить выбранные профили

Сохраняйте клон движка по стабильному пути. Из этого клона:

```bash
./install.sh --list
./install.sh codex agy
./bin/pairup --install
export PATH="$HOME/.local/bin:$PATH"
```

`--list` показывает обнаруженные CLI. Укажите установленные у вас профили.
`./install.sh` без имён выбирает все обнаруженные CLI. Глобальная ссылка `pairup`
указывает на этот клон. Сохраните PATH в настройках своей оболочки; после перемещения
клона установите ссылку заново.

Установка обновляет MCP-запись пары, глобальные инструкции, копии навыков и настройки
разрешений CLI. Существующие MCP-файлы и инструкции перед заменой копируются в `.bak`.
Пользовательский текст вокруг управляемого блока сохраняется; неоднозначно изменённый
старый блок требует ручной проверки.

Установщик проверяет MCP во временном состоянии и запускает проверки протокола.
Чтобы проверить существующую конфигурацию без её перезаписи:

```bash
./install.sh codex agy --check
```

Это может занимать дольше одного handshake из-за тестов. Сессия модели не запускается.
При самостоятельной работе пустой список инструментов pair MCP — нормальное поведение.

## Выбрать самостоятельную работу или пару

Для самостоятельной работы запустите `codex`, `agy` или другой CLI в целевом проекте.
Инициализация состояния, назначение писателя и сосед не нужны.

Для пары из целевого проекта:

```bash
pairup --writer codex "Изучи проект и исправь ошибку повторных запросов"
```

Запуск создаёт `.pair` при необходимости, записывает путь движка и задачу,
поднимает супервизор и две CLI-панели. Существующий `anti-mock.json` сохраняется;
новый проект получает шаблон проверки реальным источником данных из движка.
По умолчанию используется отдельный Git worktree с общим состоянием в основном
каталоге. `pairup --in-place` выбирает текущий checkout.
Фиксируется только писатель. Критиком выбирается другой доступный CLI;
`pairup --swap agy` заменяет его. Повторный `pairup` подключается к сессии.

Наличие MCP, каталога `.pair` или переменных `PAIR_STATE`/`PAIR_ROLE` само по себе
не включает парный режим. Два обычных CLI, запущенных вручную, не образуют пару.
Используйте `pairup` или `pair-duo`. Нативные субагенты возвращают результат родителю
и не захватывают отдельные парные роли. При потере MCP критик сохраняет запрет записи.

## Основная ветка целевого проекта

Ветка движка — `master`. Для целевого проекта с основной веткой `main` один раз
задайте локальную игнорируемую политику из его основного checkout перед запуском:

```bash
mkdir -p .pair
printf '%s\n' main > .pair/trunk
```

Укажите настоящее имя ветки. Приоритет: `PAIR_TRUNK`, `.pair/trunk`, закоммиченная
`.pair-trunk`, затем `master`. Worktree по умолчанию требует Git-репозиторий с уже
существующим коммитом. `--in-place` отключает создание worktree.

## Конфигурация

[cli-profiles.json](../cli-profiles.json) задаёт пути MCP, инструкций и навыков,
а также команды запуска. Установщик управляет своей MCP-записью и помеченным блоком
инструкций; остальные настройки принадлежат пользователю. По умолчанию сервер
запускается дочерним процессом. Необязательный [socket-транспорт](socket-transport-flip.md)
сохраняет отдельный демон между перезапусками парного CLI.

Для парного Codex используются `--no-daemon` и передача переменных запуска через
`env_vars` MCP-записи. Установленный Codex должен поддерживать этот флаг; проверьте
`codex --help`. См. [официальный исходник CLI](https://github.com/openai/codex/blob/main/codex-rs/tui/src/cli.rs)
и [MCP-конфигурацию](https://github.com/openai/codex/blob/main/codex-rs/config/src/mcp_types.rs).

Парный OpenCode использует флаги `--standalone --auto` из профиля. Разрешения зависят
от версии CLI: если каждый вызов требует подтверждения, проверьте MCP и разрешения
самого клиента. Режим `auto` pair-mailbox не отменяет политику разрешений CLI.

После обновления перезапустите открытые CLI для загрузки конфигурации и инструкций.
Самостоятельный MCP успешно запускается без инструментов; явно парный предоставляет
`pair_*`. Не ориентируйтесь на фиксированное число инструментов.

## Обслуживание и удаление

Для обычной работы используйте `pairup`. `finish.sh` обслуживает сам движок:
выполняет проверки и переустанавливает профили. Сначала посмотрите `./finish.sh --help`.

Для удаления интеграции уберите её MCP-запись, управляемый блок инструкций и
установленные парные навыки из выбранного CLI, сохранив остальные настройки.
В `.pair` лежат задачи, сообщения, патчи и доказательства: перед удалением состояния
сохраните нужные данные. Удаление целых каталогов настроек агентов не является
корректным способом удаления интеграции.
