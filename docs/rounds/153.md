# Round 153 — the worktree is the default, and the lifecycle trail stops rotating

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-153-worktree-default`
- **Writer**: omp · **Critic**: agy
- **Base**: `dev` (master untouched)
- **Deliverable**: `bin/pairup` launches into a worktree by default with an
  explicit `--in-place` opt-out, and every worktree's lifecycle is recorded in
  a durable, never-rotated journal at `.pair/worktree-log.jsonl`.

## The two debts

Round 152 filed two cards. This round closes the first one and answers the
question the second one was asking.

**The trail that ate the merges.** `scripts/merge-audit-trail.py` measured 97
merged PRs with 17 merge records and 80 without; ten of the missing ones
(PRs 72–75 and 77–82) were merged while the surviving journal had not yet
started. The cause is not a bug but a design: the journal rotates (four
archives, the oldest deleted), so a merge record leaves the window, and a merge
that left the window is indistinguishable from a merge that escaped the gate.
Ten were lost. The next ten will be lost the same way.

**The launch that shared a tree.** `pairup --worktree <branch>` existed and was
opt-in, so the DEFAULT launch still ran in the checkout the operator was
standing in. A dirty main worktree could swallow the round, and two launches
could share one tree.

## What changed

### 1. `pairup` runs in a worktree by default

`bin/pairup` provisions `.worktrees/chore/pair-<project>-<hash8>` and switches into
it. The branch name is DERIVED from the resolved project path, not asked for:
the same project always lands in the same worktree (so a second launch reuses
it rather than creating another), and two projects never share a branch.

`pairup --in-place` is the explicit opt-out. Outside a git repository the
launch refuses and names that flag.

The pair's `.pair` state stays in the MAIN checkout, so the supervisor and the
gates see one round and one writer with no state split.

Two directories, two jobs — and this split is what makes the worktree real.
`LAUNCH_DIR` is where the agents work; `PROJECT_DIR` is where the state lives.
Before this round the launch cd'ed into the worktree and the panes cd'ed
straight back out of it (`PROJECT_DIR` was used for both), so `--worktree` was
opt-in AND ineffective: the agents edited the checkout they were launched from
anyway.

### 2. `.pair/worktree-log.jsonl` — the durable lifecycle journal

Four events: `created`, `committed`, `merged`, `removed`. Append-only JSONL,
one object per line, never rotated.

It is written to the MAIN repository's `.pair`, never the worktree's own: a
linked worktree's directory is removed with `git worktree remove --force`, and
a journal that died with it would record nothing about the worktree that died.

The commits a branch carried are captured BEFORE the merge — the merge deletes
the branch (`--delete-branch`), and after that the shas are reachable only
through the squash commit, which is a different sha. A trail that recorded
only the squash would lose the very thing the trail exists for: which commits
the branch held.

### 3. `pairctl pr merge` writes the trail

The merge gate captures the branch's commits before `gh pr merge`, writes the
`committed` and `merged` events, and the cleanup writes `removed`. A journal
write that fails is recorded in the transcript (`worktree_journal_failed`) and
never turns a finished merge into a failed command — but it is never silent
either, because a silent missing record is exactly the escape the journal
exists to make visible.

## What this round does NOT do

- It does not move the merge trail OFF the transcript for rooms that already
  merged. The journal starts from this round; the audit's read path for old
  rooms still needs the transcript as a fallback, and that is its own round.
- It does not change `scripts/merge-audit-trail.py` to read the journal. The
  journal exists and is written; the audit reads it in the next round, with
  the transcript as the fallback for what came before.
- It does not change the round's own isolation strategy gate: a worktree for a
  TASK of a running round still needs the critic's signed plan. This round
  changes the LAUNCH environment, which is the human's decision.
