# Round 139 — a merge that escapes the sanctioned path is detected

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-139-merge-trail-audit`
- **Writer**: omp · **Critic**: agy
- **Deliverable**: the merge trail is compared mechanically — the PRs merged on
  the remote against the journal's merge records — and the historical debt is a
  number in the repo instead of a hole nobody could see.

## The defect

### 1. Nothing compared the merged PRs with the journal

`bin/pairctl pr merge` is the only sanctioned merge path, and it writes a
`pr_merged` event. Direct `gh pr merge` from a shell is a protocol violation
(PROTOCOL §10g.1) — but nothing checked whether the merges that actually
happened left a record. The journal was an append-only log of what the
machine did, and a merge done outside the path left nothing at all: no
event, no row, no trace.

Measured on this tree (2026-10-21):

```
83 PRs merged on the remote (gh pr list --state merged)
24 of them have a merge record in the journal
59 of them have none
```

### 2. The debt has two strata, and neither is healed by writing events

- **PRs 1–26** — no merge gate existed; it arrives with PR #27.
- **PRs 27–60** — the gate existed, but the journal recorded no merges until
  PR #62 (`pr_merge_record`). The gate's own verdicts for that era live in the
  archived notes, not in the transcript, so the journal cannot prove those
  merges were sanctioned.

Writing an event for a merge that happened years ago would forge the journal
— the thing PROTOCOL §10g forbids. So the debt is not healed; it is **named**:
`scripts/merge-audit-baseline.tsv` lists all 59 with the reason for each.

### 3. The journal's rotation hid the older events

The transcript rotates. The events for PRs 62–85 live in
`.pair/transcript-archive/*.jsonl`, not in the active file. A check that read
only the active file would call every one of them an escape.

## What changed

- **`scripts/merge-audit-trail.py`** — compares the merged PRs on the remote
  with the journal's merge records (`pr_merged`, `pr_merge_repaired`,
  `pr_merge_forced`) from the active transcript *and* its rotated archives.
  A merge the journal knows nothing about and the baseline does not name is a
  failure, and the PR is named.
- **`scripts/merge-audit-baseline.tsv`** — the known debt, 59 PRs, with the
  stratum of each. A new row is a decision (the debt grew), not a cleanup.
- **Fail closed** — no `gh`, no answer from `gh`, no journal, no baseline:
  each fails with a message. The check never reports success because it could
  not look.
- **PROTOCOL §10g.8 (EN + RU)** — where the audit lives, and what it does not
  claim: the historical debt is named, not healed.
- **`scripts/merge-audit-trail_test.py`** — 11 behavioural tests over real
  fixtures: a real journal, a real rotated archive, a real `gh` executable on
  the PATH. The rules this check exists for are exactly the ones a mocked `gh`
  could not see.
- **Card closed**: `the-merge-audit-trail-is-not-checked-automatically.md`.
- **Card opened**: `pr-merge-record-is-not-idempotent.md` — PR #61 carries
  two `pr_merge_repaired` events, because the repair command does not check
  whether the journal already knows the merge. Truthful, but not one event per
  merge.

## The honest limits

- **The check is a local audit, not a CI layer.** The journal is the pair's
  state, not the repository's: a CI runner has no `.pair/` and no token. What
  CI runs is the check's *logic* (the test), not the live audit.
- **The debt does not shrink.** 59 PRs were merged before the journal could
  prove anything about them, and nothing this round does makes the journal
  know them. The repair command (`pr merge-record`) can repair a *future*
  escape; it cannot repair a merge whose commit the journal never saw.
- **The audit trusts `gh`.** If the remote's list of merged PRs is wrong or
  incomplete, the comparison is wrong with it. The failure mode is visible:
  the numbers are printed every run.
- **The 47 missing `verify-map.tsv` rows stay in their card.** They need a
  per-file judgement (`bin/pairctl` has no suite at all), not a mechanical
  pass, and one theme per round is the rule.

## The proof

See the evidence recorded for this round: the full gate on the branch head,
the audit's own run over the real journal and the real remote (83 merged, 24
with a record, 59 named — PASS), the ground truth, and the critic's verdict
on the head that was merged.

## Rollback

One merge commit. The baseline is a data file: restoring the old state means
restoring it, and the check's failure mode (a new escape) is a failure, not
a silent pass.
