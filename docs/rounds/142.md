# Round 142 — the supervisor's ring reaches a full-screen TUI, not a tmux popup

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-142-tui-ring-reaches-the-screen`
- **Writer**: omp · **Critic**: agy · **PR**: #89 · **Merge commit**: `4a02b15`
- **Deliverable**: the pilot's wake reaches the agent's screen. The doorbell is
  typed into the neighbour's composer — the same path the server's own doorbell
  uses, with the same guards — and the tmux popup stays only as the fallback
  for a pane that refuses.

## The defect

`bin/pairpilot`'s `ring()` woke a silent peer with one `tmux display-message`.
tmux draws that popup in **its own message area, outside the pane's rendered
region**. A full-screen TUI (OpenCode, agy, omp) owns that region and repaints
it, so the text never reaches the agent's screen. Measured on a live pane:

```
tmux display-message -t 56:0.1 -d 4000 "[pair] PROBE popup from umputum"
tmux capture-pane -p -t 56:0.1 | grep "PROBE popup"
-> popup visible in pane capture: False
```

The same pane took the composer's path fine: `composer_line` returned
`' | Ask anything... "Fix broken tests"'` and `is_composer_empty` said the
composer was free. So the transport worked and the pilot was using the one
that cannot work.

The shape of the failure is the supervisor's own escalation ladder ending at a
popup nobody could see. The room's pilot log shows it: a wake file per role,
then `pilot_wake_pending` / `pilot_wake_api` / `pilot_push_quiet` — and no
peer ever reacting. The room looked silent while the peer was merely unaware.

## What changed

- **`bin/pairpilot`** — `ring()` now wakes in the order the door deserves:
  1. **the API adapter**, when the CLI has one (only `opencode`): it wakes the
     session without typing into it;
  2. **the neighbour's composer**, through `composer.deliver`, with the
     server's own guards: the role's own CLI must sit in that pane (a shell
     would run the pointer as a command — 97 `[pairpilot]: command not found`
     lines in galatour), the pane must be provably ours
     (`pane_belongs_to_project`), and the composer must be visible and free
     (`ring_refusal_reason`);
  3. **the popup**, as the fallback for a pane that refuses. A human at a plain
     terminal sees it; a full-screen TUI never will. It costs nothing and it is
     the last resort.
- **The pointer wears the server's ring shape** (`ring_prompt`), so
  `pointers.own_pointer_length` recognises the pilot's own leftovers and the
  pilot erases them before typing again — a leftover pointer holds the
  composer and makes every later delivery refuse. The pilot cleans up both
  shapes it can leave: the mail doorbell and the report doorbell.
- **One letter is one message in the peer's pane.** The ring and the queued
  push are two doors to the same peer: a ring that lands takes the queue's
  place, and the mail nudge is skipped instead of arriving second. The report
  text stays behind the ask trigger — the ring is a doorbell, not a report.
- **`mcp/pair_mailbox/pointers.py`** — the pilot's report doorbell is a shape
  of its own: a mail wake points at the mailbox, where the letter is; a report
  wake has no letter and points at the state (`See pair_state.`), where the
  cause is visible.
- **`docs/PROTOCOL.md` / `docs/PROTOCOL.ru.md`** — the wake path is named
  honestly (the doorbell first, the popup as the fallback), and the ring is
  documented as the second, narrower door: a cause, never a report, with the
  ask trigger still governing the report text.
- **The card is gone**:
  `docs/backlog/pilot-ring-popup-is-invisible-in-a-full-screen-tui.md` — the
  backlog check reports 0 high debt.
- **`scripts/file-size-baseline.tsv`** — the pilot grew (2480 → 2644 lines) and
  so did its test file (3360 → 3534); both rows carry the reason.

## The proof

Nine new cases in `bin/pairpilot_test.py`'s `TestRingReachesTheScreen`, run
against a fake tmux that behaves like a full-screen TUI (the pane holds an
input field; `send-keys` puts the text into it; `capture-pane` shows it back):

- the wake lands in the peer's pane, and the pointer says where to look and
  what the cause is;
- the pointer is the server's own shape, so the pilot can recognise it;
- the pilot clears its own leftover pointer (both shapes) instead of wedging
  the neighbour's composer;
- a report wake points at the state, not at an empty mailbox;
- a busy composer is never typed into — the popup is the fallback;
- a foreign pane is never typed into — the popup is the fallback;
- a shell pane is never typed into — the pointer would run as a command;
- one letter produces one message in the peer pane: the queued nudge is skipped.

The pin that said "typing into the composer is banned" was **deleted, not
re-pinned** — it described the defect, and re-pinning it would have frozen the
bug as a rule.

## The honest limits

- **The report doorbell points at the state, not at the mailbox.** There is no
  letter behind a report wake, so the pointer says `See pair_state.` — the
  peer must read the state to see the phase and the writer. The report TEXT
  stays behind the ask trigger either way.
- **The wake does not deliver the letter.** The doorbell says where to look;
  the peer still has to call `pair_read`.
- **A busy composer still ends in a popup**, which a full-screen TUI does not
  see. The throttle is 5 minutes per role, so a peer that keeps its composer
  busy stays unreachable by the pilot.
- **The popup is not a wake for an agent.** It is a human's signal. It is kept
  because it is free, not because it works for a TUI.
- **The adapter still comes first for `opencode`** — it wakes the session
  without typing into it, so the composer is the fallback there, not the
  primary.

## Rollback

One merge commit (`4a02b15`). The old ring was not wrong about the throttle or
about the popup; it was a wake addressed to a screen that does not exist.
