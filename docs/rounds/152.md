# Round 152 — the parked findings become cards, the stale one says the truth, and the paid one is deleted

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-152-parked-findings`
- **Writer**: omp · **Critic**: agy
- **Base**: `dev` (the human's directive: dev only, `master` untouched)
- **Deliverable**: two backlog cards with the measurements behind them, one
  existing card that says what is still open instead of what was true a day ago,
  and one card deleted because its debt was paid seven rounds ago.

Source: round 151's own card. It found two debts on the way, fixed one class of
them, and parked two with the words "the next round's question, not a change to
slip in here". This is that next round — for the part of it that is filing, not
fixing.

## Why this round exists at all

Round 151 ended with its work merged and two findings in prose:

> **What this leaves open.** The rotation window is still four archives, so the
> next ten merges will be lost the same way.

> The PRODUCTION behaviour is deliberately unchanged: `tool_pids` still reads an
> empty argv as "the process is gone".

Prose in a round card is a promise with no owner. The protocol's rule is
explicit: a finding that is real but out of scope goes to a `backlog` note, and
**the writer moves each note into `docs/backlog/<slug>.md`**. A card has a
title, a severity, a place in the tree, a red-proof and a "what to do". A
paragraph in a closed round's card has none of those — and in six months nobody
will read round 151's card looking for the next round's homework.

So this round files what round 151 parked, measures it properly, re-scopes the
card round 151 made false, and deletes the card whose debt round 115 had
already paid.

## The four artifacts

### 1. `docs/backlog/journal-rotation-window-eats-merge-records.md`

Round 151's gate failed on `scripts/merge-audit-trail.py`: 97 merged PRs, 17
with a merge record, 80 without, and ten of the missing ones (PRs 72-75, 77-82)
had been merged between `2026-10-20T06:52:50Z` and `2026-10-21T08:56:02Z` —
while the surviving journal now begins at `2026-10-21T09:03:18Z`, the merge of
PR 83.

Measured again this round, on the same room:

| file | rows | span | merge events | bytes |
|---|---|---|---|---|
| `transcript.jsonl` (active) | 496 | 10-26T20:31 .. 23:18 | 11 | 162 974 |
| `transcript-archive/1.jsonl` | 944 | 10-25T22:28 .. 10-26T20:31 | 7 | 262 379 |
| `transcript-archive/2.jsonl` | 1025 | 10-21T20:53 .. 10-25T22:28 | 4 | 262 209 |
| `transcript-archive/3.jsonl` | 988 | 10-21T09:03 .. 10-21T20:53 | 6 | 262 321 |

There is no `4.jsonl`. With `TRANSCRIPT_ARCHIVES = 4`
(`mcp/pair_mailbox/store_core.py:43`) the shift loop runs from index 3 down to
1 and **deletes** index 3 (`store_core.py:478-485`), so three archives plus the
active file is the whole reachable history — and `3.jsonl` is already at
262 321 bytes against a 262 144-byte cap. The next rotation deletes it.

The card does not propose "keep more archives". It names the actual conflict:
**the journal and the merge trail want opposite things.** The journal rotates
because the active file must stay small (the tail-read path and `pairctl log`
both care about its size). The merge trail must remember every merge forever,
because it is the audit's entire ground truth and a merge that falls out of the
window is indistinguishable from a merge that escaped the gate. The thing that
is safe to delete is exactly the thing the audit must never lose.

The fix the card names: move the merge trail OFF the rotating journal.
`mcp/pair_mailbox/ledger.py` already exists, is per-round, and is not part of
the rotation — the same shape as the facts anchor round 137 built ("a fact that
vanishes with a rotation is not an anchor"). The audit reads it there and keeps
the transcript as a fallback for old rooms.

### 2. `docs/backlog/pairmcpdoctor-has-no-tests-and-still-sleeps-blind.md`

Round 151 introduced `mcp/pair_mailbox/wait_until.py` and rewrote
`bin/pairmcprestart` onto it. It did NOT touch `bin/pairmcpdoctor` — the
sibling that does the same job over every role.

Verified in the code this round:

```
$ grep -n "time.sleep" bin/pairmcpdoctor
153:    time.sleep(6)
161:    time.sleep(2)
169:        time.sleep(3)
$ grep -n "wait_until\|wait_for_condition" bin/pairmcpdoctor
(no output)
```

The same defect, the same cure, one file over — and the cure is already written
and tested. The sibling's three named ceilings
(`bin/pairmcprestart:45-47`) and its three `wait_for_condition` calls
(`bin/pairmcprestart:152,165,178`) are the template.

The card carries two more measurements of the same file:

- **Its picker classifier is a pile of negations.** `pair_row_state()` decides
  between `connected` / `failed` / `disabled` / `present` / `absent` with
  `"connected" in joined and "not connected" not in joined and "not " not in
  joined` — any row containing `"not "` falls through.
- **It does not use the `-J` capture at all.** It reads `capture-pane -p`, the
  terminal's ROWS. On a narrow pane a `Connected` marker that wrapped onto the
  second row reads as `absent`, and the doctor then types into a pane it
  believes is not showing a picker — the exact defect round 151 fixed for the
  composer.

### 3. `docs/backlog/pairmcpdoctor-and-pairmcprestart-have-no-tests.md` — re-scoped

This card (round 126) claimed:

> `bin/pairmcpdoctor` — MCP connection diagnostics for the roles' panes
> `bin/pairmcprestart` — restarts a role's MCP server through the agent's
> `/mcp` interface
> `scripts/verification-profile.tsv` — no row for either
> `scripts/verify-map.tsv` — no mapping for either

Round 151 made half of that untrue: `bin/pairmcprestart_test.py` now exists
(7 tests), `scripts/verification-profile.tsv` has an `mcpprestart` row, and
`scripts/verify-map.tsv` maps both the tool and its test.

The protocol's lifecycle says a fixed card is DELETED. This card was not fully
fixed, so it is neither deleted nor left as it was — it is re-scoped to what
survives: the **structural** rule that every shipped executable in `bin/` has a
test sibling or a named exemption. That rule is unwritten, and it is what let
this gap exist; it will let the next one exist.

### 4. `docs/backlog/state-kernel-seam.md` — DELETED, and the commit says why

The protocol says a fixed card is deleted and the commit message records what
closed it. This one had been sitting open since round 110 while the work it
asked for was DONE in round 115 — commit `2336d09`, "the state kernel moves to
store_core".

The card's own boundary:

> State kernel: **lines 636..1071** (436 lines) — `ProtocolError` (636),
> `_transcript_hash` (649), `verify_transcript_chain` (655), `_transcript_entry`
> (702), `_transcript_tail` (719), `class Store` (761..1071), `atomic_write_json`
> (1073), plus the constants `CHAIN_GENESIS` (634), `TRANSCRIPT_ARCHIVES`,

Measured today: **none of those symbols is in `server.py` any more.** They are
in `mcp/pair_mailbox/store_core.py` (580 lines), and `server.py` re-exports
them through one import block (`server.py:699`) so no call site changed in the
cut commit. The card's own warning — "line numbers drift with every commit"
— is exactly how it went stale: its line numbers became fiction while the
debt it named was already paid.

Its acceptance criteria, checked mechanically this round:

| criterion | check | result |
|---|---|---|
| the seam is out of `server.py` | `grep -cE "^(class Store\|def atomic_write_json\|def verify_transcript_chain\|def _transcript_hash)" mcp/pair_mailbox/server.py` | **0** |
| `store_core.py` holds them | all four symbols present | **yes** |
| call sites unchanged | `from store_core import` re-export block at `server.py:699` | **yes** |
| chain integrity proven before and after | `test_chain_breaks_loudly_on_tampering`, `test_chain_breaks_loudly_on_a_damaged_line` | **yes** |
| the rotation guards are real again | `test_rotation_keeps_the_file_under_the_cap`, `test_rotation_loses_no_entries` | **yes** |

Round 115's own card records the red-proof it ran at cut time: 299 chain rows
`ok:true` before, 314 after, a 40-row chain detecting tampering at index 20,
and the three rotation guards that had regressed to green-while-proving-nothing

So the card is closed and DELETED. A card that is fixed but left in the
directory is a card that claims to be open debt when it is not — and
`scripts/backlog-check.py` is built to refuse exactly that.

## What this round does NOT do

- **It does not fix the rotation window.** The fix changes the audit's read path
  and the merge gate's write path. It needs its own red-proof — "after a
  rotation, the audit still finds the merge" — and a code round is the honest
  place for that. It is not smuggled into a card-filing round.
- **It does not write `bin/pairmcpdoctor_test.py`.** That is code, and it needs
  the live-pane stub the sibling's test uses.
- **It does not touch `docs/PROTOCOL.md`.** The protocol has no section on where
  the merge trail lives; adding one means the Russian mirror and the parity
  gate, which is its own round.
- **It does not delete the re-scoped card.** Nothing was fixed there, so the
  "fixed card is deleted" rule does not apply — and a card that grows a second
  lifecycle (`fixed_by` on a card that was never deleted) is exactly what
  `scripts/backlog-check.py` refuses.
- **It does not touch the other 14 open cards.** The protocol says a card's
  line references rot and must be re-checked before the card is worked. This
  round re-checked the one it had grounds to re-check (the seam card, whose
  subject is a file round 115 moved). The rest are other rounds' homework,
  and auditing them here would be scope the human did not order.

## The honest limits

- The measurements in the new cards describe THIS room on THIS day. The
  archive sizes are the room's own; another room's window is a different
  number. The card says so where it matters.
- The ten lost merge events were repaired in round 151 through
  `pairctl pr merge-record` — the command the protocol names for a merge that
  bypassed the gate. The repair is truthful but it is NOT a fix: the next
  merge past the window needs the same manual work. That is what the card is
  for.
- The `pairmcpdoctor` card names the shape of the fix, not its code. The
  classifier's exact replacement (a shared module versus importing the
  sibling) is a design choice the next round makes with its own measurements.
- Deleting `state-kernel-seam.md` closes the card as the protocol reads it,
  but the card's METHOD note was worth keeping: "seam size is measured, not
  estimated". That lesson lives in round 115's card, where the cut happened.

## Rollback

One branch, squashed into one commit by the merge. Reverting THE MERGE removes
the two new cards and the re-scoping of the third, and restores
`docs/backlog/state-kernel-seam.md` — which would again claim that the state
kernel lives in `server.py`, when round 115 cut it into `store_core.py` seven
rounds ago. Nothing else in the project depends on the new cards; they are read
by `scripts/backlog-check.py` and by humans browsing `docs/backlog/`.
