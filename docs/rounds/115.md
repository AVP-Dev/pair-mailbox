## What was wrong

Two caveats the human named after round 114, both structural rather than cosmetic.

**(A) The size debt was being paid, not cured.** `mcp/pair_mailbox/server.py` stood at 4490 lines, and
`scripts/file-size-baseline.tsv` grew with it every round — each line carrying a recorded reason, so
the "cap" was really a ledger that could always be extended by writing a sentence. The repo's own card
says it: *"grows every round with a recorded reason, which is payment, not a fix."*

**(B) A silent default could masquerade as a defect.** `Store.__init__` accepted any root, and `_load`
fell back to `default_state()` when `state.json` was absent. So `Store(Path('.'))` — the human's own
typo — read as an *empty-but-valid* state: `.get()` chains returned `None`, and two green direct
results were misread as *"the file changed under me"* for two hours, chasing a defect that did not
exist. Round 114's wedge was this, not a filesystem race.

## What was done

**The seam, measured not estimated.** AST at cut time: `Store` and its four helpers occupied
`server.py:634..1129` — 496 lines, against the round-110 card's claimed 436. The card had drifted;
line numbers move with every commit. The class/kernel boundary was drawn along that measurement, not
through a functional cut (round 110's functional attempt produced `NameError`s and a revert).

**`mcp/pair_mailbox/store_core.py` is new, 596 lines.** It carries the state kernel and the rotation
caps *as `Store` class attributes* — so the rotation guards test something real again instead of
reading module constants they could never vary. `server.py` re-exports every kernel symbol, so no call
site changed in the same commit: all **17 kernel names measured identity-equal** through the re-export
(`store_core.Store is server.Store`, and likewise for the rest).

**A wrong root refuses loudly, and the bootstrap doors say so.** `Store.__init__` raises
`FileNotFoundError` naming both the path tried and the `.pair` neighbour it meant:

```
No state.json in .; did you mean .pair?
```

Creation is opt-in and *each* opt-in site names its lawful first-run reason: `pairctl task`,
`cmd_reset`, `board_snapshot`, test helpers, `bin/pairpilot`, `bin/pairwatch`, and the serve path —
because the installer's health check (`install.sh:407-438`) launches the server against an *empty*
scratch state and demands an `initialize` reply. Five pins in `StoreRootRefusalCase`
(`test_state_rotation.py`), including the literal `Store(Path("."))` that started the phantom.

**`run_ctl` no longer builds a Store for commands that deliberately ignore one.** `cmd_all` is the
cross-project reader by design (`pairctl_read.py:101-103`); constructing a `Store` before the handler
meant a typo'd `--state` fell back to `cwd/.pair`, which does not exist in a CI checkout. The Store is
now lazy: `task` is the only command permitted to bootstrap, every reader must find an existing pair.

**Transcript-chain red-proof, before and after**: 299 rows `ok:true` before the cut, 314 after; a
40-row chain detected tampering at index 20; the three rotation guards that had regressed to
green-while-proving-nothing are real again (41 passed).

The rule earned is now `docs/PROTOCOL.md` §18, mirrored to `PROTOCOL.ru.md`: **suite scope is part of
the claim.** Run the shipped command (`scripts/verify-project.sh`), not a comfortable subset; a green
run that contradicts a hypothesis indicts the harness before it indicts the code; an unexpected `None`
ends the experiment. Also §18: diagnose against the tree, not against your own harness.

The cost of learning it in CI was a round reopened twice. `baseline.tsv` rose by +3 lines
(`pairctl_authority.py` +1, `pairpilot` +2), each with the recorded reason — payment, per the standing
rule, where the alternative was deleting a comment.
