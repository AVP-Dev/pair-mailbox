## The defect this round started from

The backlog said all three things. The code did none of them.

A writer's isolation decision, taken alone, goes wrong in both directions:
too much machinery for a typo fix (a worktree per sentence), or a
thousand-line system change in one PR nobody can review. Both are the same
defect — **a decision that was never examined**. Nothing in the project
forced the decision to be written down, forced anybody to look at it, or
forced the worktree to be cleaned up when the work landed.

So the round is not "add worktree support". It is: **make the isolation
decision a declared, signed, and discharged object.**

## The five slices

The plan declared five slices, and the fifth is the record of the first four:
slice E is this card (`9b9b95d`).

### A — the strategy is a declared, checked thing (`6a0f21e`)

`mcp/pair_mailbox/isolation.py` (new, 253 lines) makes the decision a
structured value rather than a sentence:

- `parse_strategy(text)` — parses the `# Isolation Strategy` section into
  `{ok, mode, worktrees, slices, rationale, why}`. The declaration is the
  `mode:` field **and only that**.
- `decide(size_class)` — the recommendation matrix.
- `validate(strategy, diff_lines)` — the declared strategy against the
  **measured** diff.

The "and only that" is the load-bearing part. Prose is not a decision:
"No worktree is needed here" would otherwise declare a worktree, and "the
branch is round-147" would declare `in-place` — both from a sentence that
said the opposite. A fenced code block is documentation, not a declaration.

### B — the plan must state the strategy (`71be1b5`)

`plan_gate.parse_plan` now requires a fourth section, `# Isolation
Strategy`, in `mode=fix`. In `audit` it is not required: there are no
commits, so there is nothing to isolate.

This is the cheapest honest entrance, because the plan is **already**
mandatory before `implement` and **already** requires a Goal. One more
section is one more regex and one more entry in `missing` — not a second
independent barrier, which is slice C's job.

### C — a worktree is not created before the critic agrees (`6b53116`)

The backlog position was blunt: "creating a worktree is forbidden until the
official plan-ack is received".

`worktree.setup_worktree` now takes a `visa` and **refuses without one** —
and refuses when the agreed mode is `in-place`. The signature makes the
refusal fail-closed: forgetting to check is impossible, because the absence
of a visa *is* the refusal.

Two kinds of worktree, two different gates, because the question differs:

- The **launch environment** (`pairup --worktree`, `pair-duo --worktree`)
  exists before any round does. There is no round, no plan, and nobody to
  sign anything; the decision is the human's, made on the command line.
- A **task's worktree** exists inside a round, to isolate one of its slices.
  That decision belongs to the writer, and the critic signs it.

`bin/pair-duo` called `git worktree add` directly, bypassing the module
entirely; it now goes through the same gate.

### D — the worktree dies with the branch (`cf28f22`, `fd70e56`)

§19 makes a merged round branch die by construction. The **directory** that
held it did not: `gh pr merge --delete-branch` deleted the branch and left
the worktree on disk, forever, in the developer's tree.

`worktree.cleanup_worktree_for_branch` removes the worktree that held the
merged branch and prunes the records. The **main** worktree is never
touched — the repository itself is not garbage, and `git worktree remove` on
it would be a catastrophe, not a cleanup. "Nothing to clean" is a success,
not a failure: it is the normal case for a round that worked in place.

`review_gate.cmd_pr` runs the cleanup after a successful merge and records
it in the transcript as `worktree_cleaned` or `worktree_cleanup_skipped`.
Silence would leave the reader unable to tell "there was nothing to clean"
from "the cleanup failed and nobody said so" — two states with different
actions.

## Three defects my own tests found

### The cleanup targeted the wrong branch

The first `_merged_branch` read `git rev-parse --abbrev-ref HEAD` — the
branch the **merge ran from**, usually the trunk. That is not the branch
whose worktree we want to remove. A cleanup that targets the wrong branch
is worse than no cleanup, because **it looks like it worked**.

The branch now comes from GitHub: `gh pr view --json headRefName` is the
branch the PR was opened from. The remote head branch is deleted by the
merge itself, but the PR record keeps the name — verified against the live
merged PR 95 (`round-146-supervisor-watchdog`).

### The smoke passed against code that was not there

The end-to-end smoke ran in a `git clone` of this repository, and a clone
carries only **commits**. The fix was uncommitted, so the smoke exercised
the old code — and the old code reported `worktree_cleanup_skipped` while
the directory survived. That is how the wrong branch went unnoticed in the
first place: the evidence was from a tree that did not contain the change.

Re-run against the committed tree, the same smoke shows the directory gone
and the transcript carrying `worktree_cleaned`.

### The cleanup could have broken the merge

The cleanup ran **after** the merge, and my first version let an exception
escape straight through `cmd_pr`: the merge had succeeded, and the command
reported failure. The merge already happened and cannot be undone, so an
error there is recorded (`worktree_cleanup_failed`) and the command still
reports success.

My own test caught this while I was writing it — the failure mode was the
defect, not a missing import.

## The plan had to obey the rule it introduced

The published plan for this round stated its strategy in prose:
"**`in-place branch`** for this round, because the round changes the rules
of the game and should be visible as a whole". My own parser refused it:

```
parse_strategy -> {'ok': False, 'mode': None, ...,
  'why': 'the `# Isolation Strategy` section names no mode'}
```

The rule I wrote for others applied to me: prose is not a declaration. The
plan now declares `mode: decomposed`, `worktrees: 0`, `slices: 5` — five
sequential slices on the round branch — and the gate accepts it. The critic
re-acked the changed plan, and the plan gate opened.

## The honest limits

- **The thresholds are a measured compromise, not a proof.** 50 and 300
  changed lines are the matrix's numbers, not derived from a measurement of
  what reviewers actually read. They are checked against the **measured
  diff**, never against what the plan promised — a rule against the promise
  is decoration, and a rule against the fact is a rule. The numbers
  themselves are still a judgement.
- **The gate says the section exists; it does not say the section is
  honest.** `mode: worktree` with `worktrees: 0` passes the parser. The
  counts are checked for internal consistency, not against the filesystem.
- **The cleanup needs GitHub.** If `gh` is unavailable or unauthenticated,
  the branch cannot be read, and the cleanup is skipped and **recorded** as
  skipped. The stale directory stays until someone removes it by hand.
- **The round plan's own `slices: 5` is a declaration, not a measurement.**
  Nothing verifies that five slices were actually made; the count is
  checkable only by the reader of the history.
- **The Russian mirror is behind and stays behind.** `docs/PROTOCOL.ru.md`
  lacks §9b, §17 and the §6 plan-gate subsection. This round adds §21 to
  both files so the new material creates no **new** gap; it does not close
  the old one. That is a separate piece of work, deliberately not smuggled
  in here.
  *(Corrected in round 150: the mirror's gap was also reported as "§14-16",
  but those section numbers exist in NEITHER file — they are a numbering gap
  in the original, not a translation gap. Round 150 closed the three real
  gaps; §14-16 remain absent from both, as they always were.)*
- **One test file per source file is a rule this round obeyed by moving
  tests, not by splitting a source file.** `review_gate.py` grew by 98 lines
  and stays at 487 — under the 800 ceiling — so no source was split.
