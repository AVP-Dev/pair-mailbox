# Round 133 — the finalizer could not close the session it exists for

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-133-finalizer-can-close` (PR #80)
- **Writer**: omp · **Critic**: agy

## What was wrong

The session finalizer is the tool that closes a coding session: `finalize-check`
audits the tree, `finalize-plan` turns the audit into a plan, `finalize-apply`
executes the safe parts, `finalize-report` writes the marker. It was run on
this repository's own session — and it died before reading anything:

```
$ bash skills/session-finalizer/scripts/finalize-check
skills/session-finalizer/scripts/finalize-check: строка 37: /usr/bin/python3:
Слишком длинный список аргументов
$ echo $?
126
```

Exit 126, zero bytes of stdout, no verdict at all.

**1. The captures travelled through the environment.** `finalize-check` is a
bash script that ends in `python3 - <<'PY'`, and it handed its captures to
that python through environment variables:

```sh
export ROOT BRANCH BASE UPSTREAM CFG PORC DIFFCHECK_OUT DIFFCHECK_EXIT \
       STATUS_EXIT DETECT_JSON PR_RAW ARTS SKILL
```

Linux caps **one** environment string at 128KB (`MAX_ARG_STRLEN`, 32 pages).
The `ARTS` capture is the session artifact listing — every path under
`.pair/**` and `.session/**` — and a busy room has a lot of them: this
repository's own `.pair/` holds 3165 files, **166KB** of path strings. The
`execve` therefore failed with `E2BIG` ("argument list too long") before
python started. The check was not slow, not wrong, not red: **absent**, and
the shell's exit code (126) looks like a usage error rather than a broken
tool.

The same script failed in the opposite direction too: a busy `git status` or a
long `git diff --check` output would have hit the same wall, because the size
of the environment, not the size of the room, decided whether the finalizer
could run.

**2. The finalizer's own suite ran in no gate.** `skills/session-finalizer` is
a complete subsystem with 70 tests of its own
(`tests/test_apply.sh`, `test_check.sh`, `test_guards.sh`, `test_plan.sh`,
`test_report.sh`). No gate ran them:

- `scripts/verification-profile.tsv` had no row for it
  (`grep -c "session-finalizer" scripts/verification-profile.tsv` → 0);
- `scripts/verify-map.tsv` mapped the whole `skills/` tree to
  `waiting-contract`, so a change under `skills/session-finalizer/scripts/`
  selected a suite about the mailbox waiting contract;
- `scripts/verify-project.sh` did not include the suite either.

So the subsystem whose job is to close sessions had no test in any gate, and
the map claimed a coverage it did not provide. This was already filed as
`docs/backlog/session-finalizer-suite-never-runs-in-any-gate.md` (round 126).

**3. The map could not express a narrower row.** `suite_for()` picked the
**first** matching row in file order, so a directory-wide row swallowed every
subsystem under it and the answer depended on where somebody had typed the
row. A narrower row was impossible to express reliably.

## What was done

**The captures stay inside the process.** The shell now exports names and
paths only; the python takes the captures itself, with the same commands and
the same working directory:

```python
r_status = run("git", "status", "--porcelain=v1")
r_diff   = run("git", "diff", "--check")
r_detect = run("bash", os.path.join(skill, "adapters", "commands.sh"), "detect", root)
r_pr     = run("bash", os.path.join(skill, "adapters", "hosting.sh"), "pr", branch)
r_arts   = run("bash", os.path.join(skill, "adapters", "agent.sh"), "artifacts", root)
```

No environment string carries text any more, so the size of the room cannot
decide whether the finalizer runs. The grep-gate that forbids write verbs in
`finalize-check` stays green on its own terms: the fix does not delete
anything, it deletes a mechanism that made deletion necessary.

**The suite runs in the gates.** `scripts/verification-profile.tsv` gained a
row, and `scripts/verify-map.tsv` gained a narrow one:

```
session-finalizer	positive	1	bash skills/session-finalizer/tests/run.sh
skills/session-finalizer/	session-finalizer
```

**The longest row wins.** `suite_for()` now picks the longest matching row
instead of the first one, so the answer no longer depends on the order the
rows were typed in. The exact row is the longest match of all, so it still
beats every directory prefix.

**The regression test is in the suite that now runs.** `tests/test_check.sh`
case 15 builds a room whose artifact listing is 177500 bytes — over the
128KB limit — and asks for a real verdict.

```

   before: exit 126, "argument list too long", 0 bytes of stdout
```

The changed-file gate on this round's own diff: `verify-changed: suites:
session-finalizer;verify-map` — the finalizer suite ran because of this
round's change, which is the first time that sentence has ever been true.

## What a reader should take away

The tool that closes sessions was itself unreachable, and it was unreachable
exactly where it matters — a busy room. The cause was not a bug in a
condition; it was a transport choice. Passing a capture through the
environment looks free until the room grows past 128KB, and then the whole
tool disappears without a word: no trace, no red, just exit 126 and an empty
file. A subsystem like this one has to be exercised at the size it will
actually meet, which is why the regression test builds a room of 2500 files
instead of asserting the size of a constant.

The second defect is the older one, and it is the shape this repository has
been fixing since round 115: a suite that exists, passes, and is called by
nobody. Seventy green tests that no gate reaches is a claim about correctness
that nothing checks. Fixing the routing so the suite runs was the other half
of the fix — without it, the new regression test would have been one more
green test in a room nobody enters.
