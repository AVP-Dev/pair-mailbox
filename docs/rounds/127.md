# Round 127 — the audit's findings, fixed: the gates that did not check, the dead code, and the room that was not yours

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-127-audit-fixes`
- **Writer**: omp · **Critic**: agy (plan in `pair_note` kind=plan; scope rulings seq 1737, 1739)
- Machine record: `.pair/RECEIPT-127.md` (git-ignored, rebuilt by `reset`); ledger: task #131

## What was wrong

Round 126 audited the whole system and filed 16 cards. The human came back with the
point that mattered: the job was to FIX them, not to collect them. This round is that.

The findings were not cosmetic. Two of them were gates that did not check what they
claimed to check, and one of those let a wrong file reach the human's screen without
a word.

**The python syntax gate compiled 65 of the repo's 141 python files.** It derived
membership from a shebang, and 76 of the repo's python files are library modules with
no shebang at all — `heal.py`, `plan_gate.py`, `review.py`, `state_rotation.py` and
the rest of the package. A syntax error in any of them left the static gate green
while it printed "65 file(s) parse".

**The shell syntax gate checked 11 hand-listed scripts out of 32.** The 21 it did
not check included `scripts/verify-changed.sh` — the script that decides which
suites a change runs — and the whole `skills/session-finalizer/` subtree. A syntax
error in `verify-changed.sh` left "verify-project.sh --only static" green.

**The guard test had the same blind spot as the gate it guarded.** Its
`_python_files()` used the identical filter, so it could not see the gap: it proved
"every file WITH a shebang is covered" while the profile claimed "every python file
in the repo is covered". The two statements differ by 76 files, and only the second
one was written down.

**The board gate ran the PROJECT's checker.** `server.py` reached it by putting
`project_root/bin` on `sys.path` and importing by name. Three defects in four lines:
`sys.path` grew by one entry on every call with no cap; the import found the
PROJECT's `boardcheck.py`, so the gate was dead in every deployment but this one
(it logged "board check skipped" and carried on); and the same path executed
project-supplied code inside the long-lived server process, on a security-relevant
gate.

**The self-heal cap counted a lifetime, not a streak.** PROTOCOL §10f calls it
CONSECUTIVE. Nothing ever reset it, so the third failure of any kind over the
project's whole life disabled self-healing for good, and the only way back was for
a human to delete `.pair/heal-state.json` by hand — which `pairctl reset` did not
even do.

**The plan gate looked for the visa by file NAME.** It globbed `notes/verdict*.md`,
so a visa written to `notes/plan-ack.md` — the obvious kind for a plan
acknowledgement, and the name this very project uses — was invisible to it, and the
writer waited out the 24-hour window for a visa that had already been given.

**The rotation mechanism was 100 % dead in production**, and the two comments that
promised a bound the system did not have were the only trace of it.

**Seven never-called functions**, one of them a "red-proof" that returned a constant
and so could not fail.

**`bin/pair-duo` wrote into another project's room.** From a project subdirectory it
took a foreign `PAIR_STATE` on its face, wrote a WRITER into that room and launched
the panes bound to it; its default was the install directory, so the pair served
pair-mailbox itself instead of the project the operator was standing in.

**`bin/pairpilot` created a second room** under the subdirectory and watched THAT
one — and the nearer `.pair` wins every later walk-up, so the second room HIDES the
real one from the next tool that resolves by walking up.

## What was done

**The gates now check everything, and derive it from the tree.**

- `scripts/python-syntax.sh` compiles every tracked `.py` module AND every tracked
  script with a python shebang: 142 files, up from 65. Membership is derived, never
  listed.
- `scripts/shell-syntax.sh` is new: it walks the tracked tree, picks every file
  whose shebang names a shell, and parses each with THAT shell. The interpreter
  comes from the shebang, because the two differ here and the wrong one reports
  errors that are not there — `scripts/verify-project.sh` is bash and uses
  bash-only syntax, so `sh -n` fails on a valid file.
- The guard test now mirrors the CLAIM: every tracked python file must be
  compile-checked, every tracked shell script must be syntax-checked, and neither
  leg may claim the other's files. It reads the legs' own membership through a
  `--list` mode, so a leg that grew a hand-written list would be visible there.

**The board gate runs from the installation.** The checker is loaded from THIS
checkout by path — no `sys.path` change at all — and it checks the PROJECT's tree,
which is the tree the board's claims are about. When the checker cannot be loaded,
the gate says so where the operator sees it, instead of logging a line nobody reads.

**The heal counter counts consecutively.** The streak ends when a ROLE reopens a
closed round: that is the human or the peer taking the work back. It is
deliberately NOT reset at the close: the flapping case the cap exists for is
heal → close → fail → heal, and a reset there would let that loop run forever. The
auto-heal path reopens without passing through that move, so a flapping loop still
spends the cap. Both halves are tested. `pairctl reset` now removes
`heal-state.json` with the rest of the room.

**The visa is content, not a file name.** The gate reads every `notes/*.md` file,
and the refusal names where it looked. PROTOCOL §7 was updated to match.

**One resolver for the room, in two languages.** `mcp/pair_mailbox/state_resolve.py`
holds the rule; `mcp/pair_mailbox/state_resolve.sh` is its shell face. Five entry
points call it — `bin/pairup`, `bin/pair-duo`, `bin/pairpilot`, `serve.sh`,
`pairctl_read` — so the next entry point cannot get it wrong the same way. The
rule: the project root is authoritative; an inherited `PAIR_STATE` is honoured only
when it names THIS project's own room, and refused loudly otherwise, naming BOTH
rooms; an explicit `--state` is always trusted; `PAIR_TRUST_ENV=1` is the
deliberate escape.

**The dead code is gone, and the guard test that would have caught it is in place.**
Six never-called functions deleted; the seventh (`tamper_probe`, a "red-proof" that
returned a constant) replaced by a real test: a note written through `pair_note`
whose journal row is then deleted must be named and refused by `check_notes`. The
one-shot script that performed round 108's split is gone, and the phantom rows in
`verify-map.tsv` with it — plus a guard of their own, so a map row can never again
name a file that does not exist.

**The rotation mechanism is gone, and the growth it promised is filed instead.**
Round 126 found `state_rotation.rotate()` 100 % dead. Wiring it was measured before
it was written, and it does not work: the two halves of the mechanism contradict
each other (`rotate()` assumes the file holds only the active window, but `_load`
hands out the union and `_save` writes that union back), so a rotate-mutate-rotate
cycle produced 222 union rows for 131 real records. And the union-on-read makes
reads slower, not faster: 14.69 ms against 10.36 ms for one file, while the hot
file alone reads in 0.65 ms. The two comments that asserted a bound the system does
not have are gone with the module, and the real problem — `state.json` at 144 568
bytes, rewritten whole on every mutation — is filed with the measurements and the
design question it needs answered.

## What was left open, and why

- **`docs/backlog/state-json-grows-unbounded-because-rotation-needs-a-design-round.md`** —
  the state file grows without bound. Fixing it means separating the ACTIVE window
  from the HISTORY, so a reader that does not need the history does not pay for it:
  a change to the store's read path and to every consumer of the task list. That
  does not belong in a round that also fixes a syntax gate.
- **`docs/backlog/pair-state-costs-74-250ms-and-15-24-subprocesses.md`** — the
  optimization of `pair_state`, untouched: it needs a before/after measurement of

  implement the adapters or correct the table in both languages. A contract change

## What the human should know

The audit's own claim — that two of its cards were "the same class the repo had
already fixed once" — turned out to be about a ratchet that had a hole in the
middle rather than in the ends. The repo's answer to "a check whose green claims
more than it checked" was a derived membership and a guard test; the guard test had
the same filter as the gate, so the answer never actually held. That is now the
shape of every gate in the repo: derive membership from the tree, and test the
CLAIM rather than the filter.
