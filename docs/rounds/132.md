# Round 132 — the janitor counted its refusals as deletions, and audited a cache instead of the remote

- **Mode**: fix · **Autonomy**: auto · **Branch**: `round-132-janitor-honesty` (PR #79)
- **Writer**: omp · **Critic**: agy

## What was wrong

The cleanup after round 130's merges is the §20 janitor's job, so the janitor
was run: `bin/pairctl branch audit --delete`. It printed this:

```
branch audit: 7 branch(es) deleted, each with a transcript row
```

**Nothing was deleted, and no transcript row was written.** The remote had
three branches before the run and three after it (`dev`, `master`,
`round-130-backlog-gate`). The seven branches the janitor offered to delete
were not on the remote at all — they were seven `refs/remotes/` entries left
behind by earlier merges, and the run's own stderr said so, six times over:
`refusing to record: delete of round-127-audit-fixes failed: error: unable to
delete 'round-127-audit-fixes': remote ref does not exist`.

Three defects, each independently enough to produce a false green.

**1. The counter was inverted.** `delete_merged` returns `0` when the delete
succeeded and `1` when it was refused, and the caller summed those return
codes into `deleted`:

```python
deleted += delete_merged(repo, row, store, role)   # 0 = success, 1 = failure
print(f"branch audit: {deleted} branch(es) deleted, each with a transcript row")
```

So the number printed next to the word "deleted" was the number of **failures**,
and a successful delete contributed nothing. A run that deleted seven branches
said "0 branch(es) deleted"; a run that deleted none said "7". The existing test
pinned the inverted flag: it asserted `rc == 0` after a successful delete.

**2. The branch list was the local cache, not the remote.** `_remote_branches`
read `refs/remotes/`. A merged PR's branch dies on the remote — GitHub deletes
it — while its tracking ref stays until somebody fetches with `--prune`. The
janitor therefore reported branches that did not exist, classified them, offered
to delete them, and then failed to delete them. Its own docstring claimed "every
remote branch"; it never asked the remote.

**3. A second entry point that could not keep its promise.** `branch_audit.main()`
was a copy of the command handler with `store=None` hardcoded, so it could never
write a transcript row — while printing "every one with a transcript row". It was
reachable only by running the module directly, and nothing did that.

## What was done

**The remote is asked.** `_remote_branches` runs `git ls-remote --heads origin`
and parses the refs. A remote that cannot answer raises, and the audit refuses
to run — the old fail-closed rule, now pointed at the right place.

**The counter counts what happened.** `delete_merged` returns `True` only when
the branch is gone and its row is written. The summary is now three numbers
instead of one claim:

```
branch audit: 1 branch(es) deleted, 0 refused, 1 transcript row(s) written
```

The row count is not asserted, it is counted: a `_RowCounter` sits between the
janitor and the store and counts what actually went through. A refused delete is
a refusal, it is printed as one, and it makes the command exit non-zero — a
command that was asked to delete and did not has not succeeded.

**A deletion that cannot be recorded is not performed.** §20 rule 5 says the
transcript row is the only reason a deletion is defensible a month later, so
`--delete` without a store now refuses to delete anything and exits 2.

**One entry point.** `main()` is gone; `pairctl branch audit` is the only way
in, and it always has a store.

**The stale branch of this repository's own round was removed by hand.** The
janitor refused to delete `round-130-backlog-gate` — its PR (#76) was closed
unmerged, and §20 rule 3 says such a branch may be the only copy of work the
repo refused. Here it was provably not: `git diff master
origin/round-130-backlog-gate` shows the branch is strictly older than master
and holds nothing master lacks (its one unique line is the old wording of
`docs/rounds/130.md`, corrected in PR #77). It was my own scaffolding from the
previous round, and the remote branch list is supposed to carry no information
the log does not.

**`origin/dev` was left alone.** The janitor reports it as an anomaly —
§20 rule 4 names accumulators an antipattern — and says it is "reported for a
human to remove with a reason". That is a decision about a long-lived branch
that is not mine to take, so it stands as a report.

## What was measured

| what | before | after |
|---|---|---|
| branches the janitor offered to delete on this repo | 7, none of them on the remote | 0 |
| "branch(es) deleted" after a run that deleted nothing | 7 | 0 |
| summary after a delete that succeeded | "0 branch(es) deleted" | "1 branch(es) deleted, 0 refused, 1 transcript row(s) written" |
| transcript rows written by a run that promised one per deletion | 0 | one per deletion |
| exit code after a refused delete | 0 | 1 |
| branch list source | `refs/remotes/` — the local cache | `git ls-remote` — the remote |
| entry points for the janitor | 2, one of them unable to write a row | 1 |
| tests in the suite | 13 | 17 |

Red-proof, run against the real code with real git and a real bare origin:

```
A. successful delete   before: "0 branch(es) deleted", 1 row   after: "1 branch(es) deleted, 0 refused, 1 transcript row(s) written"
B. failed delete       before: "1 branch(es) deleted", 0 rows, rc 0   after: "0 branch(es) deleted, 1 refused, 0 transcript row(s) written", rc 1
C. branch gone from the remote, still in the local cache
                       before: listed as a branch   after: not listed
```

The janitor on this repository, after the fix:

```
$ bin/pairctl branch audit --delete
  report    dev                          anomaly    PR    59  accumulator: an antipattern under §20 rule 4 …
  keep      master                       trunk      PR     -  trunk: a robot never deletes this class (§20)
  report    round-130-backlog-gate       ephemeral  PR    76  no merged PR backs it (CLOSED); it may be the only copy …
branch audit: 1 anomaly, 1 keep, 1 stale, 3 branches
branch audit: 0 branch(es) deleted, 0 refused, 0 transcript row(s) written
```

Three branches: what the remote actually has.

## What stays open

Fifteen cards, all `status: open`. `origin/dev` is an anomaly for a human to
remove with a reason. Nothing else about the janitor is open: the three
defects above are fixed, and each of them has a test that fails without the
fix.

## What a reader should take away

The janitor is the one tool in this repository that deletes things, and it was
the one tool whose report was fiction: it said it had deleted seven branches
and had deleted none, and it did that while its own error output was scrolling
past on the other stream. Two of the three defects are the same shape as the
round before this one — a check whose green claims more than it checked — and
the third is the shape this repository has been fixing since round 115: a rule
that lives in a document and is not checked by anything.

The failure was only visible because the tool was run on the repository's own
state and its output was read instead of skimmed. That is the whole argument
for running the sanctioned tool, on the real tree, and reading what it says.
