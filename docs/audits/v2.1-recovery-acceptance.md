## Stop factors and repairs

- The project launch policy set `sandbox_workspace_write.network_access=false` in `launch_context.py`; Codex docs confirm network permission is separate from workspace-write and auto approval. Writer now uses `network_access=true`, retaining the workspace-write sandbox, auto-review and all existing safety checks. Critic remains read-only. (Verified against current Codex docs via Context7: https://github.com/openai/codex/blob/main/codex-rs/core/config.schema.json.)
- The source-size check previously returned a blocking failure when a file crossed a measured threshold or a recorded ceiling. That conflicted with the protocol's explicit statement that size bands are planning advice, not tripwires. `file-size-gate.sh` now emits `ADVISORY` and exits 0 for size/stale-note conditions; malformed or unreadable baseline data remains a configuration error. This behavior applies anywhere this project gate is used, so future work in another target project will not be halted by source-size heuristics.
- The host managed sandbox still denies selected writes to linked-worktree Git metadata and blocks some sockets. Git changes succeeded only through the reviewed permitted route; the project must not attempt to disable the host sandbox. Ordinary workspace edits and tests do not require disabling it.
- Test daemon leakage was caused by detached servers surviving fixture cleanup. `test_socket_transport.py` now owns and terminates its child processes; launch cleanup validates the exact state lock before signaling; `pair_test_base.py` adds fixture-scoped cleanup and pairup integration calls it. The post-cleanup host inventory found 0 temporary-state daemons and 2 expected project daemons. No production/user process was targeted by the cleanup.
- `ppp` alone is not a known system pointer. Deleting it automatically could destroy actual user input. In the inspected live tmux panes it was absent, so it was not blocking this task. The safe pointer cleanup only handles recognized system-message suffixes.

## Current conclusion

The system is **not yet proven ready for unattended autonomous use**. The restart failure was reproduced: a live session could attach without consuming the selected task, and the first Writer daemon could be absent until the Critic had started. Both defects now have code and regression coverage in this unmerged Work3 branch; a real isolated task #3 verified selected-task delivery into the intended Worktree. WorkerPool/Coordinator runtime integration, dependency/priority scheduling, Goal Acceptance Gate, real model subagent flow, and complete A–J task acceptance remain unfinished or untested. GitHub push/PR itself passed in the isolated private repository. The connected runtime still runs old `master`, so these changes are not active in the user's normal project session until the branch is promoted and MCP daemons reload.
