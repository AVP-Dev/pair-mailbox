# Раунд 16 — статический HTML-дашборд пары

## Что выяснено до плана (факты, не догадки)

1. **Страница не может читать `.pair/` сама.** С `file://` браузер не даёт `fetch()`
   локальных файлов (CORS), а запуск сервера запрещён задачей. Значит «в реальном
   времени» = генератор перезаписывает HTML, а открытая страница перезагружается
   сама. Никакого чтения файлов из JS.
2. **`docs/theme-tokens.md` в этом репозитории нет.** Он лежит в
   `agent-starter-kit/docs/theme-tokens.md` — источнике, на который прямо ссылается
   `docs/project-structure.md` §2. Копируем в `docs/theme-tokens.md`, чтобы контракт
   токенов был локальным и на него ссылалась вёрстка.
3. **Гейт считает исходниками** `.py .sh .ts .js .mjs .cjs` + исполняемые без
   расширения (`scripts/file-size-gate.sh:92-106`). `.html` и `.css` под гейт не
   попадают, но всё равно держим ≤300 — иначе это просто грязь.
4. `Store.read_transcript(limit)` читает хвост с конца файла (67.5 мс → 0.4 мс на
   2 МБ, замер раунда 14) — переиспользуем, свой парсер хвоста не пишем.
5. `pairctl_read.silence_seconds/human_age` — единственная арифметика «молчит»,
   переиспользуем (вторая реализация разошлась бы).

## Что показывает дашборд

- раунд, фаза, режим (`fix`/`audit`), автономность, кто пишет и почему;
- по каждой роли: панель, pid, жив ли pid, `last_seen` + тишина в человекочитаемом виде;
- pairpilot: жив ли процесс, последняя запись `pilot.log`, свежесть `REPORT.md`,
  отказы разблокировки и рестарты из журнала;
- задачи из леджера: статус, раунд, автор, причина закрытия/отмены;
- последние события `transcript.jsonl` с цветовой раскладкой по роли и роду события.

## Решения, которые нужно подтвердить

1. **Путь вывода по умолчанию — `.pair/board.html`.** `.pair/` в `.gitignore` и
   сносится `pairctl reset`; артефакт одноразовый, держать его в git незачем.
   `--out` переопределяет.
2. **CSS и JS инлайнятся при сборке**, а не подключаются `<link>`/`<script src>`:
   один файл переносится на любую машину и открывается двойным щелчком. Исходники
   остаются отдельными файлами и остаются под гейтом.
3. **JS-ассет тестируется из `test_board_render.py`**, а не из третьего тест-файла:
   это часть собираемого бандла, и правило «один тестовый файл на один исходник»
   здесь читается как «не заводи третьего ради куска бандла». Возражение принимается.
