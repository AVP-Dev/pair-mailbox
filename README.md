# pair-mailbox

Два агента, два разных CLI, одна задача. Один пишет код, второй его ломает.
Канал между ними — MCP-сервер, который ещё и держит правила: ровно один пишет,
правки передаются запечатанным патчем, каждый отказ попадает в аудит.

Никакой настройки. Склонировали — работает.

## Установка

```sh
git clone <url> pair-mailbox && cd pair-mailbox
./install.sh
```

Установщик сам находит установленные CLI, регистрирует в каждом MCP, раскладывает
навыки, дописывает инструкции — и **проверяет**, что сервер реально отвечает.
Молчаливый отказ формата мы ловили дважды, поэтому проверка настоящая: запускаем
ту же команду, что записали в конфиг, и делаем handshake.

```sh
./install.sh --list    # какие CLI найдены
./install.sh --check   # только проверить, ничего не меняя
./install.sh codex     # поставить одному
```

Требуется `python3` 10+ без зависимостей.

## Как работать

Две сессии в одном проекте, разные CLI: `opencode` + `agy`, или `opencode` + `codex`,
или `codex` + `claude` — любые два из установленных. Одна и та же пара не годится:
обе сессии получат одну роль.

Роль = имя CLI, зашивается при установке. В примерах ниже `<писатель>` и `<критик>`
— это имена ваших двух CLI, а не конкретные слова.

В любом окне напишите:

```
работаем вместе: починить ретраи при 502
```

Агент читает задачу и код, потом зовёт `pair_claim(reason="почему я")`. Кто первый —
пишет, второй ломает. Дальше разговаривают через `pair_*` сами, без вас.

В папке проекта — только этот проект, без чужих:

```sh
bin/pairchat --once        # переписка этого проекта и выход; отказы красным
bin/pairchat               # то же, но следить, выход по Ctrl-C
bin/pairwatch              # поймает зависшего агента
bin/pairctl status
```

Один проект — по умолчанию. Смешанная выдача мешает читать, поэтому включается
самим человеком и только когда это нужно:

```sh
bin/pairctl all                    # таблица: все проекты, кто пишет, кто давно молчит
bin/pairchat --all --once          # вся переписка сразу, у каждой строки метка проекта
bin/pairchat --once ~/work/blog    # ровно один названный проект
```

Фильтры: `--messages-only`, `--no-notes`, `--since 60`, `--all-notes`.

`pairctl all` ищет `~/work/*/.pair`. Свои пути — `PAIR_SCAN='~/work/*/.pair:~/src/*/.pair'`.
Код возврата `3` означает, что есть зависший проект.

## Инструменты

| инструмент | кто | что |
|---|---|---|
| `pair_state` | оба | авторитет, задача, фаза, слушает ли сосед |
| `pair_claim` | оба | взять авторитет с объяснением, почему ты; отказ если занят |
| `pair_release` | держатель | отдать авторитет самому, с причиной |
| `pair_advance` | вперёд писатель, **назад любой** | фаза; откат открывает раунд заново |
| `pair_send` / `pair_read` | оба | переписка; метку ставит сервер |
| `pair_patch_*` | критик предлагает, писатель проверяет | патч с SHA-256, глоб запрещён |
| `pair_note` | оба | долговременные заметки: plan, decision, finding, verdict, handoff |
| `pair_transcript` | оба | аудит, включая отказы |

## Правила

Полный контракт — `docs/PROTOCOL.md`. Коротко:

1. Писатель ровно один. Захват — гонка, но с объяснением: прочитал задачу, потом
   претендуй, и скажи почему. Причина видна соседу, если его отказали.
2. Отнять авторитет нельзя. Передать может только держатель сам или человек через
   `pairctl`. Сообщение соседа авторитет не двигает.
3. Критик не правит файлы. Он предлагает патч, писатель сверяет хеш перед применением.
4. `done` нельзя поставить поверх непрочитанного. Откат фазы доступен обоим.
5. «Сосед согласился» — не одобрение. Одобрение даёт человек.

## Навыки

| навык | что |
|---|---|
| `pair-work` | автономный цикл: план → код → ревью → тесты → PR |
| `pair-chat` | как общаться через `pair_*` |
| `pair-audit` | проверка, что тесты реальны, а не замоканы |
| `root-cause` | 5 почему, до кода |
| `pair-backlog` | куда девать дефекты вне объёма задачи |

## Структура

```
mcp/pair_mailbox/server.py    сервер, 13 инструментов, отказы
bin/pairctl                  смена авторитета, логи, заметки, `all` по всем проектам, `why`
bin/pairchat                 переписка: одного проекта или всех, `--once` печатает и выходит
bin/pairwatch                детектор зависшего агента
cli-profiles.json            форматы MCP по CLI — добавить свой = добавить строку
install.sh                   установка с проверкой
docs/PROTOCOL.md             контракт
docs/RUNBOOK.md              как пользоваться, зависло, продолжить, вторая задача
docs/SETUP.md                установка по CLI вручную, если скрипт не справился
```

## Тесты

```sh
python3 mcp/pair_mailbox/test_protocol.py
```

Интересны не «зелёные», а отказы: второй писатель, сосед лезет в авторитет,
патч подменен после печати, glob вместо точного пути, два процесса через stdio.
